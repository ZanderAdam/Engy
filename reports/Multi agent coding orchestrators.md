# Use PTY for people, MCP for state

Engy should keep its design of PTY dispatch plus MCP reply tools, but the PTY must only carry text to the worker and show the session to the human. It must never be the proof that something happened. Status should come from process exit and hooks, delivery from a tracked receipt, and "done" from checks the worker cannot fake. The best public match is Orca: it stores the message, types only a short pointer into the terminal, and escalates when a worker stops without a final report. The main warning is Gas Town, where PTY text merged with human typing, and where success was printed with zero bytes delivered. For #854, make all agents visible by default, but do not make them all writable by default: a human can be typing in a hand-opened terminal, and no tool in the notes has fully solved this. Keep the default near 3 active workers, and use parallel work for independent tasks only, because the best benchmark shows that agents on overlapping code do worse than one agent. The notes hold no evidence of any start-of-day summary (#2632) or any URL that opens a terminal (#2631). They do show what such features need, by analogy with status lists and jump keys. No tool publishes a failure rate, so the pattern choices here rest on source code, docs and bug reports, not on measurement.

## All tools solve the same five problems in different ways

Local vendor tools push a structured event to the lead when a worker stops, so the lead does not poll. Third-party tools use three methods. Tools that own the process read a JSON or SDK stream, tools that keep the real TUI use hooks, and only Claude Squad depends on screen scraping ([Claude Squad](https://github.com/smtg-ai/claude-squad/blob/main/session/tmux/tmux.go), [Orca hooks](https://github.com/stablyai/orca/blob/main/src/main/agent-hooks/README.md)). Hooks are also imperfect: a `Stop` can fire while background subagents run ([Paradev #8120](https://github.com/ParadevAI/Paradev/issues/8120)), and in cmux a large `Stop` payload was lost ([cmux #25096](https://github.com/manaflow-ai/cmux/issues/25096)).

Known failures fall into four groups. First, signals are lost or late: Claude teams users report 5 to 62 minute delays and lost final reports ([#76500](https://github.com/anthropics/claude-code/issues/76500)), and "sent" can mean only "stored" ([#98998](https://github.com/anthropics/claude-code/issues/98998)). Second, slots leak: finished Codex subagents still count against the limit ([#22779](https://github.com/openai/codex/issues/22779)). Third, "done" is false: agents skipped requested files in **67.9%** of OverclaimBench runs, and **80.4%** of the incomplete runs were misleading ([preprint](https://arxiv.org/abs/2609.20812)), though this covers file review only. One team found that **24 of 265** "done, tests pass" claims failed a re-check ([survey post](https://redreamality.com/blog/coding-agent-done-claims-verification-survey/)). Fourth, design diverges: on overlapping code, two agents reached about **25%** success, about half of one agent doing both jobs, and messaging gave no significant gain ([CooperBench](https://arxiv.org/html/2601.13295)).

Cost is also real. Overstory's own example, with no public data, shows about 6.7x the tokens for 25% less time ([STEELMAN](https://github.com/jayminwest/overstory/blob/ff38f3f/STEELMAN.md)). Gas Town's author says it "fell apart" after a model update ([Willison](https://simonwillison.net/2026/Aug/4/)). Ruflo shows a different trap: an audit found that `agent_spawn` wrote a record and started no process ([#1896](https://github.com/ruvnet/ruflo/issues/1896)).

## Engy should copy tracked delivery and evidence-based completion

Engy already has several of the right parts: bracketed paste with a separate Enter, an idle-gated inbox, hooks for activity, and a hold after `StopFailure` (`docs/system/features/terminal-relay.md`). The patterns below are the next steps. They are listed by value, and the order is my judgment from the failure reports.

| Copy | Source | What it means for Engy |
|---|---|---|
| Separate "written", "delivered" and "acted on" | Vendor bug reports, [cmux states](https://github.com/manaflow-ai/cmux/blob/main/docs/agent-messages.md) | A PTY write is not delivery. For Claude workers, use `UserPromptSubmit` for the matching turn as the delivery signal. The notes did not confirm whether Engy already does this |
| Separate "turn ended" from "work done" | [Orca stop report](https://github.com/stablyai/orca/blob/main/src/main/runtime/orchestration/worker-turn-stop-report.ts) | `settledBy: 'hook'` proves only that the turn ended. Show it as "stopped, no reply", with a reason and the last output |
| Reply carries evidence, and the server checks it | [Survey post](https://redreamality.com/blog/coding-agent-done-claims-verification-survey/), [Metaswarm](https://github.com/dsifry/metaswarm/blob/33d39f7/README.md) | Add commit hash, commands, exit codes, files changed and "not verified" items to `terminal_reply` |
| Short pointer in PTY, body in store | [Orca](https://github.com/stablyai/orca/blob/main/src/main/runtime/orchestration/formatter.ts) | A short line limits paste loss, and the body can be read again after a failure |
| Tie delivery to a process incarnation | [Orca contract](https://github.com/stablyai/orca/blob/main/src/main/runtime/orchestration/mailbox-pointer-delivery-contract.ts) | A restart cannot deliver to the wrong session |
| Store facts, derive status at read time | [Agent Orchestrator](https://github.com/OrchestratorInc/agent-orchestrator/blob/b7091d8/docs/architecture.md) | This closes #854 gap 5 (in-memory state) and removes stored stale status. Engy's SQLite is enough, and Dolt is not needed |
| A failed probe or silence means "unknown" | [Orca](https://github.com/stablyai/orca/blob/main/skill-guides/orchestration.md), [Agent Orchestrator](https://github.com/OrchestratorInc/agent-orchestrator/blob/b7091d8/docs/architecture.md) | Never kill a worker or mark it dead on silence alone. Add a distinct usage-limit state, because a limit block looks like a hang ([Gas Town #4887](https://github.com/gastownhall/gastown/issues/4887)) |
| Retry limit that the agent cannot bypass | [Orca: 3 failed starts](https://github.com/stablyai/orca/blob/main/skill-guides/orchestration/references/recovery-and-cleanup.md) | Stops spawn loops such as [Codex #14841](https://github.com/openai/codex/issues/14841) |
| End the turn and wait for a push | [Orca](https://github.com/stablyai/orca/blob/main/skill-guides/orchestration.md) | Engy's `[engy-notice …]` push already matches this. Keep it |
| Fail closed on permissions | Counter-example: [Crystal](https://github.com/stravu/crystal/blob/main/main/src/services/panels/claude/claudeCodeManager.ts) | Mark agent text as agent text, and keep "approved by a human" as a separate state that an agent cannot set |

Engy should avoid six patterns. Do not use screen text as a status signal or as a result channel: Paradev's `terminals_read` returns a rendered view, "not a full transcript" ([read.ts](https://github.com/ParadevAI/Paradev/blob/main/packages/mcp/src/tools/terminals/read.ts)). Do not send Escape as recovery, and do not report success after a fallback, because both failed in Gas Town ([#4610](https://github.com/gastownhall/gastown/issues/4610)). Do not let a full queue fail in silence: a P0 escalation sat about 24 hours behind reminders ([#4634](https://github.com/gastownhall/gastown/issues/4634)). Do not build a role hierarchy before a need exists: Gas Town's concepts are widely called overwhelming ([Appleton](https://maggieappleton.com/gastown)), and Cursor's integrator role "created more bottlenecks than it solved" ([Cursor](https://cursor.com/blog/scaling-agents)). Do not build a merge queue yet, because sending a conflict back to the branch owner is the cheap common default ([Gas Town](https://github.com/gastownhall/gastown/blob/466aa41/internal/refinery/batch.go)). Do not call `Stop` the only exit from Running: a mechanical backstop must exist ([cmux #8613](https://github.com/manaflow-ai/cmux/issues/8613)).

Two limits apply to this advice. A structured protocol would give stronger signals, Overstory moved to headless workers, and Symphony uses `codex app-server` with no terminal. But Overstory lost its hook guards in headless mode ([design doc](https://github.com/jayminwest/overstory/blob/ff38f3f/docs/headless-hooks-design.md)), and bare scripted Claude skips hooks and project MCP servers ([headless docs](https://code.claude.com/docs/en/headless.md)). PTY therefore stays the right choice while human takeover matters. It also needs a smoke test on each CLI update, because one Claude Code version ignored all submit keys in tmux ([#52812](https://github.com/anthropics/claude-code/issues/52812)). Sources also conflict on mid-turn input: Gas Town says that text cancels in-flight tool calls ([#4607](https://github.com/gastownhall/gastown/issues/4607)), and Orca's contract says that input queues. The notes did not test this, so Engy should keep its idle gate.

## The #854 proposal is sound, with three changes

The scope-filter design fits the evidence, because a role needs no new subsystem until it has a distinct tool scope. The table gives a position on each item in the task. Rows marked "my judgment" have no direct evidence in the notes.

| #854 item | Position | Basis |
|---|---|---|
| Role: UI toggle or implicit | Listing is implicit for all agents. Dispatch to terminals that were not connected needs a role that the human sets | My judgment, from the typing risk. Claude's per-session accept, hold or refuse setting is the nearest model ([docs](https://code.claude.com/docs/en/cross-session-messaging)) |
| Human-typing risk | Treat this as the top risk. Add a per-session opt-out, exclude plain shells, and hold delivery on recent keystrokes | A Gas Town input-collision report has been open since February ([#1216](https://github.com/gastownhall/gastown/issues/1216)), and another reports 9+ typing events with zero delivered ([#4610](https://github.com/gastownhall/gastown/issues/4610)). cmux holds delivery while a human prompt is open |
| May create worktrees | Yes, for writers on separate tasks, with an explicit base branch and a setup step | One worktree per task is the norm. Claude's worktrees start from the default branch, which is a trap ([docs](https://code.claude.com/docs/en/sub-agents)). Setup is a known gap ([#260](https://github.com/smtg-ai/claude-squad/issues/260)) |
| 64 KB buffer and `lines` | Accept, for debugging only. Do not use it for results or status | Orca forbids steering through a terminal and sends a bounded stop report |
| Depth ≤ 2 | Accept | Claude defaults to three layers and Cursor allows one nesting level. Overstory's leaves sit at depth 2 |
| Higher count limit | Allow fan-out to 5, but warn above 3 active writers, and limit items that wait for review | Reports cluster at 2-4 agents, or 3-5 teammates ([Kilo](https://blog.kilo.ai/p/how-7-kilo-code-engineers-run-up), [Claude](https://code.claude.com/docs/en/agent-teams)). No measured limit exists. Willison lands one significant change at a time ([post](https://simonwillison.net/2025/Oct/5/parallel-coding-agents/)) |
| Durable dispatch state | Accept, and raise the priority | The mature systems keep state outside agent context, in files, SQL or a tracker |

The task omits three items. Add an evidence check and a "stopped, no reply" state, because cross-worktree runs raise the cost of false "done". Add a startup check that the worker has loaded the MCP tools, because the reply path depends on them, and Codex workers also stop at trust and approval prompts (`docs/memory/facts/20260801213557-codex-dispatch-workers-are-not-hands-off-two-interactive-gat.md`). Add a duplicate-work check before dispatch, because duplicates made up 23% of categorized rejected agent PRs ([arXiv 2601.15195](https://arxiv.org/html/2601.15195)). Use the orchestrator for dispatch and tracking of independent units, and let the human decide scope and land changes. Sequential work lost 39-70% under every multi-agent setup in one non-coding study ([Google Research](https://research.google/blog/towards-a-science-of-scaling-agent-systems-when-and-why-agent-systems-work/)). Keep repeated orchestrator tasks away from Engy's own tooling, given Gas Town's "fiddle with Gas Town itself" failure. Prompt regression checks also matter, because a model update can break an orchestrator with no code change.

## The notes hold no start-of-day summary, but they support option 1 of #2632

**No tool in the notes documents a morning or start-of-day summary, and a search of the notes for those terms found nothing.** The evidence below is indirect. The nearest match is Claude's agent view: it lists background sessions from all projects by default, with six states, a one-line summary per row and PR labels. `claude agents --json` exposes the same state to scripts, and the docs say not to parse the files behind it ([agent view](https://code.claude.com/docs/en/agent-view)). This supports option 1 in #2632: a read-only tool over stored session data, with the skill on top. Users also ask for this view. One Emdash user asked for an overview of running and completed tasks ([#3348](https://github.com/generalaction/emdash/issues/3348)), and Vibe Kanban users asked to register outside terminal sessions ([#3293](https://github.com/BloopAI/vibe-kanban/issues/3293)). Conductor's backlog, in progress, in review and done groups show a task-level view that is separate from agent run state ([0.35.0](https://www.conductor.build/changelog/0.35.0-workspace-status)). The summary should show both levels.

The reports suggest four design rules. Put items that need the human first, because review is the limit: Faros links high AI adoption with 5X median review time, though this is correlational and vendor data ([Faros](https://faros.ai/research/ai-acceleration-whiplash)). Show "claimed done" and "verified" as different things, and repeat a worker's text only as a claim. Show why work stopped overnight, including usage limit, failed, waiting and unknown states, because a limit block looks like a hang. Use a cursor for changes since the last read, as Conductor's `list_messages` does with `after` ([MCP docs](https://www.conductor.build/docs/api/mcp)); the notes do not show this used for a summary.

Resuming has its own traps, which the read-only scope of #2632 helps to avoid. A restart redid closed Gas Town work ([#4698](https://github.com/gastownhall/gastown/issues/4698)), so check that the task is still open before resume. Unsubmitted text survived into a new session ([#4610](https://github.com/gastownhall/gastown/issues/4610)). A resumed cmux session stayed "running" until its next `Stop` ([#13024](https://github.com/manaflow-ai/cmux/issues/13024)). The notes cannot say if an on-demand skill beats an always-visible page. The evidence covers live views, and none of it tests a daily digest. Option 3 therefore stays open, and the skill is a cheap way to learn.

## The notes hold no terminal URLs, but they define what #2631 must do

**No tool in the notes documents a URL or deep link that opens a specific terminal.** The notes also have nothing on clickable links in xterm, or on `/t/<sessionId>` against a search parameter, so these choices rest only on the analysis in #2631. The nearest evidence is jump actions inside one app. Antigravity's Alt+J goes to the next subagent that waits for confirmation ([docs excerpt](https://antigravity.google/docs/cli/commands/agents/)). The Codex approval overlay names the source thread, and `o` opens it ([docs](https://learn.chatgpt.com/docs/agent-configuration/subagents)). cmux marks the waiting pane with a blue ring and has a notification panel ([README](https://github.com/manaflow-ai/cmux/blob/main/README.md)). These show the main reason to jump: a worker needs a human now. A later "next waiting terminal" link would serve that need directly, but it stays outside #2631's scope.

Three lessons apply to #2631. The link must land in the real session, because Claude peek replies cannot answer a permission dialog and the user must attach ([agent view](https://code.claude.com/docs/en/agent-view)). The link needs clear behaviour for sessions that have gone, because Orca's finished workers close themselves unless `--keep-open` is set ([guide](https://github.com/stablyai/orca/blob/main/skill-guides/orchestration.md)); the closed-session message in #2631 covers this. The session ID must also identify one exact session, following Orca's process incarnation idea, so that a link never opens a replaced session. One design difference needs a decision: Claude background sessions resume on attach or reply, while #2631 requires that a dormant link does not auto-restore. The notes favour neither option. The #2631 choice is the safer one, because opening a link then changes no state, and Emdash had a closed restore retry-loop bug ([#3260](https://github.com/generalaction/emdash/issues/3260)).

Build order is not in doubt: #2631 already blocks #2632, and the session list from #2632 can serve #854. All three then share one read-only source for session state and links.

## Conclusion

The research changes the question for #854. Orchestration primitives are now common, and Engy already has most of them. The scarce parts are honest state and safe input: knowing that a message arrived, that a worker really finished, and that a human is not typing. Engy can gain here because the human already sits in the same web app as the terminals, so the same data can serve the agent lead, the morning summary and the jump links.

The largest gaps are in the evidence. No study compares PTY delivery with structured protocols, and none compares an agent coordinator with a human coordinator on the same coding tasks. Orca is the best design model, but the notes hold no data on how well it works in practice, and its star count needs a check. Engy should therefore record its own delivery failures, false "done" results and review queue depth from the first release, because no public source gives these numbers.
